# REST FOREST POS — Android (Sprint 5 = cassa + KDS + ESC/POS)

Kotlin / Jetpack Compose POS app for Slice Pizza, designed to run on the
Huawei MatePad (10″ Android tablet) in landscape.

| Sprint | What landed |
|---|---|
| 3 | Cassa skeleton: PIN sign-in, dish grid, cart, mock payment buttons. |
| 5 | **Kitchen Display System** (PIN 9999 → grid of order cards). **ESC/POS thermal-printer integration** via DantSu 3.3.0 — USB-OTG **or** TCP/9100 with a mock-server fall-back. Room schema → v2 with a real migration. |

Real fiscal printing (LIFE PAY Cloud, Sprint 6) and acquiring (INPAS
SmartSale, Sprint 7) remain deliberately stubbed.

## Stack

| Concern | Choice | Notes |
|---|---|---|
| Language | Kotlin 2.0.21 (K2) | |
| UI | Jetpack Compose + Material 3 | tablet-first, landscape locked |
| DI | **Hilt** | picked over Koin because (a) it is the AOSP-standard, (b) Android Studio understands the graph natively, and (c) `hilt-navigation-compose` already wires `SavedStateHandle` for free |
| Local DB | Room 2.6 | schemas exported to `app/schemas/` so the PowerSync work in Sprint 4 has a baseline |
| Settings | DataStore Preferences | wired through DI but no consumers yet |
| Images | Coil 2.7 | for menu thumbnails (Supabase Storage URLs land in Sprint 4) |
| Money | `Money(kopecks: Long)` value class | no `Double`, ever |
| PIN hashing | BCrypt cost 10 | `at.favre.lib:bcrypt` |
| Min / Target / Compile SDK | 26 / 35 / 35 | min 26 matches the Quick Resto reference and the MatePad |

> Note on modularisation. The Sprint 3 brief asked for a multi-module
> layout (`core/database`, `feature/auth`, …). We deliberately consolidated
> into one Gradle module organised by package — the per-module Gradle config
> overhead is hard to justify until the surface stabilises in Sprint 5. The
> package boundaries already mirror the requested module names, so the split
> is a mechanical `apply plugin: com.android.library` change later.

## Domain primitives

* `core/domain/Money.kt` — `value class Money(val kopecks: Long)`. All prices,
  totals and fiscal amounts go through it. `Money.format(locale)` renders
  `1 290 ₽` / `1 290,50 ₽` with locale grouping.
* PIN handling: `AuthRepository.verifyPin` loads all active cashiers and
  calls `BCrypt.verifyer().verify` in constant-time. The raw PIN never
  reaches Room.

## Room schema (v1)

| Table | Key fields |
|---|---|
| `cashier` | `id`, `name`, `pinHash`, `role`, `isActive` |
| `category` | `id`, `name`, `sortOrder`, `colorArgb` |
| `dish` | `id`, `categoryId` (FK), `name`, `priceKopecks`, `imageUrl`, `isAvailable`, `sku` |
| `dish_modifier` | `id`, `dishId` (FK), `name`, `priceKopecks`, `isRequired` |
| `order` | `id`, `cashierId` (FK), `status`, `createdAt`, `totalKopecks`, `paymentMethod` |
| `order_item` | `id`, `orderId` (FK), `dishId` (FK), `qty`, `modifiersJson`, `priceAtSaleKopecks` |

`order` is quoted as `` `order` `` because the unquoted form is a reserved
SQL keyword. Foreign-key constraints are declared on every relation.

## Build & verify

### Prerequisites

* macOS / Linux. (Windows is OK, use `gradlew.bat`.)
* JDK 17 or 21 (the wrapper builds with 17-target bytecode; if your default
  JDK is 22+ the AGP 8.7 toolchain rejects it — install JDK 21 with
  `brew install openjdk@21` and point `JAVA_HOME` at it).
* Android SDK with `platforms;android-35` and `build-tools;35.0.0`. The
  build also accepts `platforms;android-34` if you bump `compileSdk`.

### From Android Studio

1. **File → Open** and choose `rest-forest-pos-android/` (the folder with
   `settings.gradle.kts`). Studio will auto-create `local.properties`
   pointing at your SDK; if it does not, copy `local.properties.example`.
2. Let Gradle sync. First sync downloads ~700 MB of dependencies.
3. Hit **Run** with the **`app`** configuration. There is no device emulator
   shipped — run on the MatePad (USB debugging on) or any landscape-capable
   AVD with API 26+.

### From the command line

```bash
# Set the JDK if your system default is too new:
export JAVA_HOME=$(/usr/libexec/java_home -v 21)

cd "rest-forest-pos-android"
./gradlew :app:assembleDebug          # produces app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:lint                   # static analysis — warnings OK, errors fail the build
```

### Installing on the Huawei MatePad

Option A — `adb`:

```bash
adb devices                           # confirm the MatePad is connected (USB debug on)
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Option B — Files app:

1. Copy `app/build/outputs/apk/debug/app-debug.apk` to the MatePad via USB
   or Cloud (e.g. send through Telegram to the till operator account).
2. Open the file in the Files app, allow "Install from unknown sources"
   when prompted, tap **Install**.

The app launches into the PIN screen. Try `1111` / `2222` / `3333`.

## Code-style guardrails

* No `!!`. Use `?: error("…")` for invariants we proved upstream
  (see `MainActivity` and `PosViewModel`).
* No `LaunchedEffect(true)` — every effect has an explicit key.
* No money in `Double`. Every value crossing a layer boundary is `Money`.
* `ViewModel` extends `androidx.lifecycle.ViewModel`, exposes
  `StateFlow<…>` only — no `LiveData`.
* Strings live in `res/values/strings.xml` (en) and `res/values-ru/strings.xml` (ru).
* Every `@Composable` screen has at least one `@Preview` (`AuthScreen`,
  `PosScreen`, `CartPanel`).

## Sprint 5 — Kitchen Display + ESC/POS

### Roles

| PIN | Role | Lands on |
|---|---|---|
| 1111 | cashier (Иван) | POS cassa |
| 2222 | cashier (Мария) | POS cassa |
| 3333 | manager (Алексей) | POS cassa |
| **9999** | **kitchen (Кухня)** | **KDS screen** |

The chef signs in with 9999 → the [`KitchenScreen`](app/src/main/kotlin/ru/slicepizza/restforest/feature/kitchen/KitchenScreen.kt)
opens — adaptive grid of order cards, per-card timer that recolours at 5 min
(jaune) and 10 min (rouge), `[В работе] / [Готов]` buttons, top-bar counters,
"Переустановить связь" printer button. A short beep fires on each new card.

### Wiring the printer

Two interface modes live in [`PrinterConfig`](app/src/main/kotlin/ru/slicepizza/restforest/feature/printing/PrinterConfig.kt):

```kotlin
val mode: PrinterConfig.InterfaceMode = InterfaceMode.Tcp   // ← change to .Usb when hardware arrives
const val TCP_HOST: String = "10.0.2.2"                     // Android emulator → host machine
const val TCP_PORT: Int = 9100                              // ESC/POS raw 9100
```

#### Mode A — TCP (current default, for development)

Used both for the **mock server** (below) and for any future Ethernet
thermal printer. The Xprinter XP-Q200 II has an optional LAN port — once
configured with a static IP, set `TCP_HOST` to that IP and rebuild.

#### Mode B — USB-OTG (real hardware)

When Petr's Xprinter / Атол лента arrives:

1. **Plug**: Huawei MatePad USB-C ↔ USB-OTG adaptor ↔ printer USB-B.
2. **Power**: connect the printer's 24 V brick.
3. **First launch**: Android shows "Open RestForestPos when this USB
   device is connected?" — tick "Always" and tap **OK**. Vendor IDs the
   app already recognises live in
   [`res/xml/usb_printer_device_filter.xml`](app/src/main/res/xml/usb_printer_device_filter.xml).
4. **Flip the config**: change `PrinterConfig.mode` to `InterfaceMode.Usb`,
   rebuild with `./gradlew :app:assembleDebug`, reinstall.
5. **Verify**: sign in with PIN 9999 → tap "Переустановить связь" in the
   top bar → green "Принтер OK" appears.
6. **First print**: from the cassa side (PIN 1111), add Маргарита → pay
   → check the strip of paper.

If the printer doesn't appear, run on the MatePad:
```
adb shell dumpsys usb | grep -i printer
```
and add the device's vendor-id (decimal) to `usb_printer_device_filter.xml`.

### Running the mock TCP server (no hardware required)

```bash
cd rest-forest-pos-android
python3 tools/mock_kitchen_printer.py
# Optional: simulate 20 % packet drops to exercise the retry path:
python3 tools/mock_kitchen_printer.py --simulate-errors-pct 20
```

Then on the device / emulator: sign in as cashier (1111), add anything to
the cart, pay. The mock prints an annotated ESC/POS transcript to stdout:

```
================================================================
[2026-05-11T14:32:01] connection from 10.0.2.16:53480
  received 412 bytes — annotated transcript:
┊ [1b40] ESC @  — initialise printer
┊ [1b6101] ESC a 1 — align centre
>> SLICE PIZZA — КУХНЯ
…
┊ [1d5641] GS V A — full cut after feed
```

If the emulator can't reach `10.0.2.2` change `TCP_HOST` to your LAN IP or
run `adb reverse tcp:9100 tcp:9100`.

### How a kitchen ticket flows

```
Cassa "Pay" tap
        │
        ▼
OrderRepository.recordPaidOrder
   ├── saves OrderEntity + OrderItemEntity rows
   └── PrintQueueRepository.enqueue
            ├── EscPosFormatter.renderKitchenTicket → DantSu markup
            ├── PrintJobDao.upsert(status="pending")
            └── WorkManager.enqueueUniqueWork(KEEP, exponential back-off)
                     │
                     ▼
PrintQueueWorker.doWork
   ├── for each pending job → PrinterRepository.printAndCut
   │       (TCP or USB depending on PrinterConfig)
   └── status="done" | retry | status="failed" after MAX_RETRIES
```

Failed jobs land in red on the kitchen screen counter; the "Переустановить
связь" button is the manual recovery.
